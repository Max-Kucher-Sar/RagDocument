# RagDocument

Помощник по документам с ответами и ссылками на источники. Загрузка PDF, DOCX, TXT, MD, XLSX и XLS. Модели выполняются в Ollama, поиск — в Qdrant. Все компоненты запускаются через Docker Compose.

## Запуск одной командой

Нужны установленный Docker Engine, запущенный Docker daemon и Docker Compose v2 с командой `docker-compose`. Из папки проекта:

```sh
docker-compose up -d --build
```

Создавать `.env`, устанавливать Python, Ollama или Qdrant на компьютере отдельно не нужно. При первом запуске нужен интернет для скачивания образов, зависимостей и моделей.

Команда автоматически:

1. Собирает образы приложения и подготовки моделей.
2. Запускает контейнеры Ollama и Qdrant.
3. Ждёт готовности Ollama и скачивает отсутствующие `qwen3:4b-instruct` и `qwen3-embedding:0.6b`.
4. После успешной подготовки моделей запускает контейнер приложения. Его стартовый модуль дополнительно ждёт готовности Qdrant и наличия обеих моделей.
5. Открывает приложение на **http://localhost:8000**.

Первый запуск может занять несколько минут. Уже имеющиеся модели в Docker volume не скачиваются повторно. При повторном запуске с сохранёнными образами, volume моделей и без изменения настроек подготовка не требует повторной загрузки весов.

Проверка состояния и журналов:

```sh
docker-compose ps -a
docker-compose logs -f ollama-init app
```

`ollama-init` со статусом `Exited (0)` — нормальное состояние: это одноразовая подготовка моделей. `app` должен перейти в `healthy`. Если скачивание завершилось ошибкой, посмотрите журнал `ollama-init`, устраните причину и повторите команду запуска.

Остановка с сохранением данных:

```sh
docker-compose down
```

Для запуска требуется работающий Docker; сам Docker Engine эта команда не устанавливает.

## Сервисы, сеть и хранение

| Сервис | Назначение |
| --- | --- |
| `ollama` | Запускает обе локальные модели |
| `ollama-init` | Проверяет наличие моделей и скачивает недостающие |
| `qdrant` | Отдельная серверная векторная БД |
| `app` | FastAPI, обработка документов, интерфейс и ссылки |

Приложение использует внутренние адреса `http://ollama:11434` и `http://qdrant:6333`. Порты Ollama и Qdrant не публикуются на компьютер. Снаружи доступен только интерфейс на `127.0.0.1:8000`.

Именованные Docker volumes:

- `ollama_models` — веса моделей;
- `qdrant_data` — векторы и их метаданные;
- `documents` — оригиналы и извлечённый текст.

Volumes переживают пересоздание контейнеров и `docker-compose down`. Команда с `down -v` удалит их вместе с данными. Для резервной копии документов сохраняйте одновременно `qdrant_data` и `documents`.

Файлы из прежнего каталога `data/` автоматически не импортируются в volumes. Если документы ранее загружались вне Docker, загрузите их повторно через интерфейс.

## Необязательная настройка

Все значения по умолчанию уже заданы в `docker-compose.yaml`. При необходимости создайте `.env` по образцу `.env.example`; Compose прочитает его автоматически. Внешние ключи API для моделей не нужны.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_PORT` | `8000` | Порт интерфейса на компьютере |
| `APP_TOKEN` | пусто | Необязательный токен доступа к приложению |
| `CHAT_MODEL` | `qwen3:4b-instruct` | Модель ответов |
| `EMBEDDING_MODEL` | `qwen3-embedding:0.6b` | Модель смыслового поиска |
| `EMBEDDING_DIMENSIONS` | `1024` | Размерность векторов embedding-модели |
| `OLLAMA_TIMEOUT` | `300` | Ожидание ответа модели в секундах |
| `OLLAMA_NUM_CTX` | `8192` | Контекстное окно в токенах |
| `OLLAMA_NUM_PREDICT` | `1200` | Максимальная длина генерации в токенах |
| `QDRANT_COLLECTION` | `documents_ollama_qwen3` | Коллекция векторов |
| `MAX_UPLOAD_MB` | `20` | Максимальный размер файла |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `1200` / `180` | Размер и перекрытие фрагментов в символах |
| `TOP_K` | `6` | Сколько найденных фрагментов передать модели |
| `SCORE_THRESHOLD` | `0.25` | Минимальная косинусная близость |

После изменения настроек снова выполните `docker-compose up -d --build`. Для смены embedding-модели или её размерности укажите новую коллекцию и загрузите документы заново. Смена модели ответов не требует переиндексации. Адреса сервисов и путь `/data/documents` задаются самим Compose; старые `OPENAI_*`, `QDRANT_PATH` и настройки адресов из прежнего `.env` в контейнер не передаются.

Если задан `APP_TOKEN`, введите его в интерфейсе. Он хранится в localStorage браузера, чтобы ссылки открывались в новых вкладках. Для очистки удалите значение из поля и нажмите «Войти».

По умолчанию Ollama работает без обязательного GPU. Для NVIDIA с настроенным доступом GPU в Docker предусмотрен дополнительный файл; он требует Compose 2.30+:

```sh
docker-compose -f docker-compose.yaml -f docker-compose.gpu.yaml up -d --build
```

## Документы и источники

1. Загрузите файлы и дождитесь индексации.
2. Отметьте документы для поиска и задайте самостоятельный вопрос.
3. Нажмите номер источника или его карточку: откроется извлечённый текст с выделением фрагмента.

| Формат | Координаты источника |
| --- | --- |
| PDF | Физическая страница с 1; можно открыть оригинал на этой странице |
| DOCX | Абзац или таблица и строка |
| TXT / MD | Строки извлечённого текста |
| XLSX / XLS | Лист, номер строки и диапазон ячеек |

Excel читается построчно с адресами ячеек. Первая непустая строка листа повторяется как подписанный контекст для понимания столбцов. Скрытые листы тоже читаются; пустые строки пропускаются, исходные номера сохраняются. Оригинал можно скачать из просмотра источника.

XLSX использует сохранённые результаты формул; при их отсутствии показывает текст формулы с пометкой, что результат не вычислялся. XLS читает сохранённые значения. Пересчёта формул, макросов, чтения диаграмм и изображений нет. Даты выводятся в ISO-формате; оформление валют и процентов может отличаться от Excel. В объединённых ячейках значение сохраняется только в исходной заполненной ячейке.

Лимиты: 20 МБ на файл, 2 млн символов, 5000 фрагментов; PDF — 2000 страниц; Excel — 100 000 строк и 256 столбцов на лист, суммарно до 1 млн просматриваемых ячеек. Сканы PDF требуют предварительного OCR. В DOCX не читаются колонтитулы, сноски и надписи внутри рисунков. TXT/MD должны быть UTF-8; номера строк относятся к тексту после удаления пустых строк по краям.

Ссылки строятся сервером по сохранённым координатам, несуществующие номера источников отклоняются. Проверяйте выводы модели по показанному тексту. Поиск нескольких строк Excel не заменяет точный расчёт по всей книге. Вопросы независимы: история видна в текущей вкладке, но не отправляется модели и не сохраняется после обновления страницы.

## Проверки в контейнерах

Быстрые автоматические тесты с временным Qdrant и тестовыми ответами модели:

```sh
docker-compose --profile test build test
docker-compose --profile test run --rm --no-deps test
```

Проверка настоящего ответа Ollama и серверного Qdrant на временном Excel после обычного запуска:

```sh
docker-compose --profile smoke run --rm smoke
```

Она использует отдельную коллекцию с уникальным именем, проверяет ответ, ссылки и отказ при отсутствии данных, затем удаляет свою коллекцию и временные файлы. Пользовательские документы не затрагиваются. Сервисы `test` и `smoke` не запускаются обычной командой `up`: они включены только в соответствующих профилях.

## API и учебное руководство

Swagger: http://localhost:8000/docs. Для защищённого API передавайте `Authorization: Bearer <APP_TOKEN>`.

- `POST /api/documents` — multipart-поле `file`.
- `GET /api/documents` — список документов.
- `DELETE /api/documents/{id}` — удаление файла и индекса.
- `POST /api/ask` — `{"question":"Какой срок возврата?","document_ids":["UUID"]}`. Без списка — поиск по всем документам; пустой список — ни по одному.
- `GET /api/documents/{id}/chunks/{index}` — текст и координаты источника.
- `GET /api/documents/{id}/file` — оригинальный файл.
- `GET /api/status` — состояние Ollama и список недостающих моделей.
- `GET /healthz` — готовность Qdrant и наличие обеих моделей, без раскрытия настроек; используется Docker healthcheck.

Объяснение технологий и упражнения — в [docs/LEARNING.md](docs/LEARNING.md).

Приложение рассчитано на персональное использование. Публичный доступ требует отдельной настройки HTTPS, аутентификации и ограничений загрузок. Разделения документов между пользователями нет.
